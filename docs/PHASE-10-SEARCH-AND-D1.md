# Phase 10 검색 감사와 미등록 검색 보고

## 검색 품질

Seed 120개(verified 100개, needs_research 20개)의 이름과 모든 별칭을 자동 검사한다. 검증된 품목은 기존 상세 URL로, 조사 중인 품목은 배출 답변이나 상세 링크 없이 확인 중 상태로 연결한다. 이름·별칭 충돌은 기존 Seed 검증기가 build를 실패시킨다. 검색 순서는 이름 정확히 일치 → 별칭 정확히 일치 → 이름 앞부분 → 별칭 앞부분 → 이름·별칭 부분 일치이며, 그 다음에 기존 오타 1글자 및 카테고리·검색 키워드 보조 검색을 적용한다. 동점은 slug 순서로 고정한다. verified 여부로 문자열 일치 순서를 바꾸지 않는다.

이번에 추가한 별칭은 `달걀껍데기`(계란껍질), `데스크톱`, `데스크톱컴퓨터`, `본체컴퓨터`(데스크탑컴퓨터) 네 개다. 프라이팬, 계란껍데기, 달걀껍질, 휴대전화, 스마트폰, 모니터, 에어후라이어, 휴대용배터리, 형광램프는 이미 등록돼 있다. `김치 냉장고` 등 일반적인 띄어쓰기 차이는 검색 정규화로 처리해 별칭을 중복 저장하지 않았다. 뜻이 다른 품목으로 해석될 가능성이 있는 표현은 추가하지 않았다.

검색 스크립트와 Seed 인덱스는 내용 해시가 포함된 파일 이름을 함께 사용한다. `/assets/*`의 장기 브라우저 캐시가 과거 스크립트·Seed를 새 HTML과 섞어, 운영 화면에서 이미 verified인 품목을 `확인 중`으로 보여 주는 문제를 막기 위한 조치다. 해시 파일 이름은 검색 자산에만 적용하며 공개 페이지 주소·canonical·sitemap은 바꾸지 않는다.

## D1 집계 보호

브라우저는 개인정보·URL·전화번호처럼 보이는 값, 제어문자, 장문·반복 입력을 missing 전송 대상으로 삼지 않는다. 서버는 클라이언트 상태를 신뢰하지 않고 같은 입력을 재검사한다. 빈 값, 60자 초과, 정규화 후 한 글자인 미등록어, 지원하지 않는 문자도 저장하지 않는다. 알려진 이름·별칭·검색 fixture·조사 중 품목은 D1에 접근하지 않는다. 정상적인 미등록 품목명만 안전한 binding을 사용해 UPSERT 한 번을 수행하며, 같은 키는 행을 추가하지 않고 `search_count`를 늘린다. D1 키의 기존 규칙(앞뒤 공백 제거·연속 공백 축약·소문자화)은 유지해 운영 중인 행과 분리되지 않게 한다. 입력 원문과 거부 사유는 API 응답에 포함하지 않는다. 이 규칙은 기존 D1 행을 수정하거나 삭제하지 않는다.

## 운영자 읽기 전용 보고

저장소 루트에서 `npm run report:missing-searches`를 수동 실행한다. Node.js가 고정 Wrangler 3.114.17을 별도 shell 없이 실행하므로 Windows PowerShell에서도 동일한 인수를 사용한다. Cloudflare 로그인이 필요하다. 스크립트는 **Production DB** `burimttukttak-missing-search-prod`에 `--remote --env production --json`으로 다음 SELECT 하나만 실행한다.

```sql
SELECT normalized_query, display_query, search_count, first_seen, last_seen
FROM missing_searches
WHERE search_count >= 2
ORDER BY search_count DESC, last_seen DESC
LIMIT 20;
```

결과는 터미널에만 표시한다. 개인정보·URL 형태가 섞인 기존 행은 출력 전에 제외하고, 다섯 허용 필드 외의 값은 버린다. 보고를 Git 파일에 자동 저장하지 않으며, 명령에는 UPDATE·DELETE·migration이 없다. 운영자는 출력에 민감한 정보가 보이면 외부에 공유하지 말고 별도로 수동 검토해야 한다. 검증 테스트는 SQL과 명령 인수만 정적으로 검사하며 Production D1에 접속하지 않는다.
